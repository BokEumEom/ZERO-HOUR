# Scaffold a new arcade game

Creates a new in-shell game (the same architecture as Zero Hour — registered via
`SY.registerGame`, driven by the shell's rAF loop). For a *linked standalone*
game instead (its own page/loop, like `shepards-dog`), this skill does not
apply — copy `js/games/shepards-dog/` and add a `register.js` link card.

## Inputs

Ask the user for (or infer from their prompt):

- **id** — lowercase, no spaces (e.g. `starfall`). Used as the directory name,
  the `registerGame` id, and the records namespace (`SY.store.forGame(id)`).
- **title** — display name in CAPS (e.g. `STARFALL`).
- **blurb** — short hub-card tagline in CAPS (e.g. `NEON GRAVITY ARCADE`).
- **accent** — hex color for the hub card (e.g. `#5aa7ff`).

## Steps

1. **Create the module directory** `js/games/<id>/` with three files, copied from
   [templates/](templates/) with the `__ID__` / `__TITLE__` / `__BLURB__` /
   `__ACCENT__` placeholders replaced:
   - `game.js`   — engine: state + simulation. Exports `SY.game`.
   - `render.js` — Canvas 2D drawing. Exports `SY.render`.
   - `main.js`   — lifecycle (`enter`/`exit`/`frame`) + `SY.registerGame`.

   > Note: `SY.game` / `SY.render` are shared singletons. If more than one
   > in-shell game must coexist, namespace them (e.g. `SY.games[id]`) instead of
   > overwriting — but for a single active game the shared globals match the
   > Zero Hour pattern.

2. **Wire the load order in [index.html](../../../index.html)** — add three
   `<script>` tags in dependency order (`game → render → main`), placed with the
   other game modules and BEFORE the React/Babel CDN block:
   ```html
   <script src="js/games/<id>/game.js"></script>
   <script src="js/games/<id>/render.js"></script>
   <script src="js/games/<id>/main.js"></script>
   ```
   The `/build-standalone` script picks these up automatically from the load order.

3. **Add an E2E hub-card check** to [test/e2e/harness.html](../../../test/e2e/harness.html)
   mirroring the existing Shepherd's Dog card assertion — confirm the new game's
   card is listed on the hub by its title.

4. **HUD / screens** — gameplay HUD and menu/end screens are game-specific HTML.
   Add them to `index.html` near the other games' markup, or have the game draw
   its HUD on-canvas. Keep them hidden until the game's `enter()` runs.

## Invariants to respect (do not regress)

- **Seeded RNG**: all gameplay-affecting randomness (spawns, drops,
  probabilities) MUST use the per-run `s.rng()` seeded via `SY.makeRng`.
  `Math.random()` is for cosmetics only. The template wires `s.rng` in `start()`
  to make the correct path the default. See the `game-conventions` skill.
- **React-free core**: `game.js` / `render.js` / `main.js` must not reference
  React and must run if the CDN scripts fail.
- **No per-frame allocations** in `update()` / `render()` (60fps hot path) — run
  the `performance-analyzer` agent after gameplay/render work.

## Verify

After scaffolding, run `pwsh test/run-all.ps1` (or open `index.html`) and confirm
the new card appears on the hub and the game enters without console errors. The
`/build-standalone` bundle must be regenerated by the user before shipping.
