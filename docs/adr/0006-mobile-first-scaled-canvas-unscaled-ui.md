# ADR-0006: 모바일 First — 스케일되는 캔버스 / 스케일 안 되는 UI 분리

- **상태**: 적용됨 (2026-06-12)
- **관련**: [모바일 First 플랜](../plans/2026-06-12-mobile-first-ui.md)

## Context

기존 구조는 HUD와 모든 화면 오버레이가 960×664 `#stage` 안에 있어 게임과 함께
`transform: scale()`로 축소됐다. 세로 폰(0.39배)에서 9px 라벨이 3.5px가 되는 구조적 문제.
한편 데일리 공정성([ADR-0002](0002-seeded-rng-daily-fairness.md)) 때문에 논리 아레나
960×600은 기기와 무관하게 고정이어야 한다 — 아레나 반응형은 선택지가 아니다.

## Decision

1. **스케일 경계를 캔버스로 한정**: `#stage` = `<canvas>` + CRT 효과만 (논리 960×600).
   HUD·메뉴/결과/일시정지/안내 화면·조이스틱·버튼은 뷰포트 레벨 fixed DOM으로,
   스케일 없이 CSS 반응형(`clamp()`, flex-wrap, `env(safe-area-inset-*)`)으로 렌더링.
2. **오리엔테이션별 레이아웃** (`fit()`이 `body.portrait|landscape` 클래스 부여):
   - 세로: HUD 솔리드 바 → 폭 맞춤 아레나 → 잔여 하단은 전용 터치 영역
     (손가락이 아레나를 가리지 않음). 오브젝트 축소(~0.4배)는 사용자가 수용한 트레이드오프.
   - 가로/데스크탑: contain-fit 중앙 + HUD 반투명 오버레이.
3. **게임 엔진(`js/game.js`) 무변경** — 레이아웃·입력 표면만 바뀌고 시뮬레이션은 동일.
   조이스틱 입력 수신처만 `#stage` → `#viewport`로 확장 (phase 가드는 기존 유지).
4. 몰입 보강: Fullscreen API(시작 제스처 편승 자동 요청), PWA manifest + 아이콘
   (서비스 워커 제외 — 오프라인은 standalone.html 담당), 햅틱은 피드백 모듈인
   audio.js에 통합 (`setMuted`와 동일한 설정 패턴).

## Consequences

- (+) 어떤 화면 크기에서도 UI 텍스트는 자연 크기 — 모바일 가독성 문제 구조적으로 해소
- (+) 공정성·점수·시뮬 회귀 위험 0 (엔진 비변경, 기존 테스트가 안전망)
- (−) `.screen`이 뷰포트 전체를 덮으므로 레터박스 영역까지 어두워짐 (의도된 디자인)
- (−) 세로 모드 아레나는 작다 — 정밀 플레이는 가로 권장 (터치 영역 힌트로 안내)
