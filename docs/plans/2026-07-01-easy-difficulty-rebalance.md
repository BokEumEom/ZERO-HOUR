# EASY 난이도 완화 — 계획 및 실측

- **상태**: 완료
- **작성일**: 2026-07-01
- **관련**: [[difficulty-feel]] (2026-06-26, 난이도 간 차이를 벌린 이전 작업)

## 배경

사용자 리포트: "게임 난이도가 easy 단계도 너무 어려운 것 같습니다." 이전 작업
(difficulty-feel, 2026-06-26)은 **난이도 간 격차**를 벌렸을 뿐(터렛/적 종류/surge
규모), EASY 자체의 절대적 난도는 검증한 적이 없었다.

## 조사 방법 — 회피 봇 시뮬레이션

정적 수치 비교로는 "실제로 얼마나 위험한지" 알 수 없어, `test/unit/helpers.mjs`의
vm 샌드박스 + `G.update(dt)` 수동 스텝을 이용해 **가장 가까운 위협으로부터
회피하는 단순 봇**을 만들어 EASY/NORMAL 각 25회 시뮬레이션(무작위 시드 free-play)했다.
봇은 기뢰·바위·오브·적 탄막·보스(+코어)·터렛으로부터 반발 벡터를 합산해
`SY.input.ax/ay`를 조종 — 텔레그래프(surge warn 등)는 무시하는 보수적(=사람보다
못한) 플레이어 근사.

### 수정 전

| 지표 | EASY | NORMAL |
|---|---|---|
| 사망률(60초 내 hp 0) | 7/25 (28%) | 25/25 (100%) |
| 무피격 런 비율 | 0/25 | 0/25 |
| 첫 피격까지 평균 시간 | 24.8s | 15.2s |
| 평균 동시 위협 수(피크) | 20.4 | 18.2 |

EASY와 NORMAL의 위협 밀도가 거의 안 갈렸다(20.4 vs 18.2) — 기존 격차 확대
작업(surgeMul 0.7×)이 실제 화면 밀도에는 충분히 반영되지 않았고, 목숨은
난이도 무관 고정 3.

## 근본 원인

1. **`player.hp`가 전 난이도 고정 3** — `game.js`에 하드코딩, DIFF 테이블에
   체력 관련 knob 자체가 없었음.
2. **스플리터 오브(R4, `s.orbs`)가 난이도 게이트 없이 전 티어 동일 스폰** —
   fence/flail/barrier/arc는 이미 `spawnMul>=1`(normal/hard 전용) 게이트가
   있었는데 오브만 빠져 있었음 (R4 작업 시 게이트 추가를 누락한 것으로 보임).
3. surge가 uncapped 스파이크라 ambient `mineCap`/`spawnMul` 완화만으로는
   체감 밀도가 충분히 안 내려감.

## 수정 (`js/games/neonvortex/game.js`, `main.js`)

- **`DIFF.easy.maxHp = 4`** (normal/hard는 3 그대로 — 데일리 공정성 불변,
  daily는 항상 normal이라 영향 없음). `combineDiff`가 `maxHp`를 통과시키도록
  추가, `freshState`가 `player.hp`/`maxHp`를 하드코딩 3 대신 `diff.maxHp`로 설정.
- HUD 하트 렌더(`main.js`)와 1UP 회복 상한(`game.js`)의 하드코딩된 `3`을
  `s.player.maxHp` 기준으로 수정 — 4번째 하트가 정상 렌더/회복됨.
- **오브 스폰에 `spawnMul>=1` 게이트 추가** — EASY에서 스플리터 오브 완전 제외
  (다른 R-계열 해저드와 동일 패턴으로 통일). normal/hard는 `spawnMul`이 항상
  ≥1이라 동작 불변 — RNG 소비 시점도 그대로라 데일리 결정성 영향 없음.
- **EASY 밀도 knob 추가 완화**: `spawnMul` 0.75→0.65, `mineCap` 9→7,
  `surgeMul` 0.7→0.55.

## 검증

- `test/unit/difficulty.test.mjs`에 5개 신규 테스트: maxHp knob/와이어링,
  daily가 easy의 여분 목숨을 절대 상속하지 않음, 1UP 회복이 `maxHp` 기준으로
  동작, 오브가 EASY에서 전혀 안 뜸(30초 관측 창), 밀도 knob 상대 비교.
- `test/unit/static.test.mjs`의 tripwire pin(`surgeMul: 0.7`)을 의도된 신규
  값(`0.55`)으로 갱신.
- 전체 스위트: 단위 268/268, E2E 66/66 그린. `standalone.html` 해시 동기화 확인.
- Playwright로 실제 EASY 런 HUD 스크린샷 — 하트 4개 정상 렌더 확인.

## 남은 고려사항

봇은 텔레그래프(surge 경고 등)에 반응하지 않는 보수적 근사이므로, 실제
플레이어 사망률은 이보다 낮을 가능성이 높다. 16% 잔여 사망률이 여전히
높다고 판단되면 `maxHp`를 5로 올리거나 `mineSpeedMul`을 추가로 낮추는 것을
다음 후보로 고려 — 단, EASY를 무의미하게 만들 위험과 트레이드오프.
